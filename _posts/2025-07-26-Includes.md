## Introduction

The **Includes** challenge on PicoCTF demonstrates how web applications load resources from multiple files — and how those files can each contain fragments of sensitive information. This challenge requires systematic inspection of all loaded resources to piece together the complete flag.

> **Challenge Description:** "Find the flag hidden across multiple files in the website."

## Environment Setup

**Required Tools:**
- A modern web browser (Chrome or Firefox)
- Browser Developer Tools (`F12`)

No additional software installation is required.

---

## Solution Walkthrough

### Step 1: Open the Challenge Website

Navigate to the provided challenge URL and read the page content.

### Step 2: Interact with the Page

Click the **"Say Hello"** button. An alert will appear saying the "Flag is in another file" — confirming the flag is split across static resource files.

### Step 3: View the Page Source and Locate `script.js`

Press `Ctrl + U` to view the page source. Find the reference to `script.js` and click on it. Inside `script.js`, you will find the **first half of the flag**.

### Step 4: Intercept `style.css` via Network Tab

Open Developer Tools (`F12`) and go to the **Network** tab. Refresh the page and look for a request to `style.css`. Click on it in the Network tab — its contents contain the **second half of the flag**.

### Step 5: Combine Both Halves

Concatenate both parts to form the complete flag.

## Key Concepts

**How Websites Load Resources:**

Web pages typically load multiple resource files — HTML, CSS, JavaScript — each served as a separate HTTP request. When developers accidentally include sensitive data in these files, attackers can discover them through source inspection and network analysis.

```
HTML page → loads → script.js  (first half of flag)
            loads → style.css  (second half of flag)
```

## Security Insights

- **All loaded resources are accessible:** CSS and JavaScript files loaded by a page are visible in the Network tab and can be inspected by any user.
- **Never hide secrets in static files:** Flags, API keys, configuration data, and credentials placed in static resources are publicly accessible.
- **Network tab is a powerful tool:** Web security assessments routinely use the Network tab to discover unexpected data leakage in loaded resources.

---

## Conclusion

This challenge illustrates that sensitive data embedded in any file loaded by a web page — whether HTML, CSS, or JavaScript — is fully accessible to any user. Complete security auditing of all static resources is an essential step in any web application security assessment.
