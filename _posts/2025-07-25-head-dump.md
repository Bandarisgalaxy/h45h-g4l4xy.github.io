## Introduction

The **Head-Dump** challenge on PicoCTF demonstrates how improperly secured API documentation and debug endpoints can leak sensitive server data. A Swagger-documented API exposes a memory dump endpoint that contains the flag embedded in the server heap.

> **Challenge Description:** "Welcome to the challenge! In this challenge, you will explore a web application and find an endpoint that exposes a file containing a hidden flag. The application is a simple blog website where you can read articles about various topics, including an article about API Documentation."

## Solution Walkthrough

### Step 1: Open the Challenge Website

Navigate to the provided challenge URL. The site presents itself as a blog covering various tech topics.

### Step 2: View the Page Source and Search for API

Press `Ctrl + U` to view the page source, then search for the keyword `api`:

```
Ctrl + F → search: api
```

### Step 3: Navigate to the API Documentation

Find and navigate to the API documentation URL referenced in the source. This typically opens a Swagger UI interface.

### Step 4: Identify the Memory Dump Endpoint

In the Swagger UI, browse all available endpoints and look for memory-related endpoints such as `/dump`, `/heapdump`, or `/actuator/heapdump`.

### Step 5: Execute the Endpoint

Click **Try it out**, then click **Execute** to trigger the endpoint.

### Step 6: Download and Search the Dump File

Download the generated memory dump file. Open it in a text editor and search for `picoCTF`, or use the terminal:

```bash
grep -a "picoCTF" <dump_filename>
```

The flag is embedded as a readable string inside the binary memory dump.

## Key Concepts

**What is a Heap Dump?**

A heap dump is a snapshot of the process memory at a given moment. It may contain live object data including passwords, tokens, API keys, and secrets stored in memory.

**Why is an Exposed Heapdump Dangerous?**

Exposing debug or diagnostic endpoints in production allows attackers to extract sensitive in-memory data, including session tokens and stored credentials.

> **Security Note:** Endpoints like `/actuator/heapdump` must always be disabled or protected behind strong authentication in production environments.

## Security Insights

- **Exposed debug endpoints** are a critical misconfiguration frequently found in production systems.
- **Swagger/OpenAPI documentation** should never be publicly accessible — it maps out your entire API attack surface.
- **Memory dumps contain live secrets:** Session tokens, passwords, and API keys stored in-memory are visible in heap dumps.
- **Principle of Least Exposure:** All administrative and diagnostic endpoints should be restricted to internal networks or secured with strong authentication.

---

## Conclusion

This challenge simulates a real-world vulnerability where leaving diagnostic API endpoints publicly accessible exposes sensitive server-side data. In production security assessments, finding an exposed `/heapdump` endpoint is a critical finding. Always restrict such endpoints and disable Swagger UI in production.
