## Introduction

The **Login** challenge on PicoCTF demonstrates the danger of **client-side authentication** — a pattern where authentication logic and credentials exist entirely within the JavaScript downloaded to the user's browser. Since the browser can read all JavaScript, any credentials stored this way are essentially public.

> **Challenge Description:** "My dog-sitter's brother made this website but I can't get in; can you help?"

## Solution Walkthrough

### Step 1: Open the Website

Navigate to the challenge URL. You are presented with a basic login form requiring a username and password.

### Step 2: View the Page Source

Right-click on the page and select **View Page Source** (or press `Ctrl + U`). Notice a link to a JavaScript file called `index.js`.

### Step 3: Analyze `index.js`

Open the JavaScript file. The authentication logic is entirely client-side:

```js
(async () => {
  await new Promise((e => window.addEventListener("load", e)));
  document.querySelector("form").addEventListener("submit", (e => {
    e.preventDefault();
    const r = { u: "input[name=username]", p: "input[name=password]" };
    const t = {};
    for (const e in r) 
      t[e] = btoa(document.querySelector(r[e]).value).replace(/=/g, "");

    return "YWRtaW4" !== t.u
      ? alert("Incorrect Username")
      : "cGljb0NURns1M3J2M3JfNTNydjNyXzUzcnYzcl81M3J2M3JfNTNydjNyfQ" !== t.p
      ? alert("Incorrect Password")
      : void alert(`Correct Password! Your flag is ${atob(t.p)}.`);
  }))
})();
```

**Key observations:**

- [`btoa()`](https://developer.mozilla.org/en-US/docs/Web/API/Window/btoa) — encodes a string into Base64
- [`atob()`](https://developer.mozilla.org/en-US/docs/Web/API/Window/atob) — decodes a Base64 string back to plain text
- The credentials are hardcoded as Base64-encoded strings inside the JavaScript
- The flag is revealed by calling `atob(t.p)` on the correct password

### Step 4: Decode the Credentials

Use the browser console (`F12` → Console tab) to decode the values:

**Decode the username:**

```js
atob("YWRtaW4")
// Output: "admin"
```

**Decode the password (which is also the flag):**

```js
atob("cGljb0NURns1M3J2M3JfNTNydjNyXzUzcnYzcl81M3J2M3JfNTNydjNyfQ")
// Output: "picoCTF{53rv3r_53rv3r_53rv3r_53rv3r_53rv3r}"
```

### Step 5: Read the Flag

The password itself is the flag — no login required. The `atob()` call in the alert directly reveals it from the JavaScript source.

## Key Concepts

**Client-Side vs. Server-Side Authentication:**

```
# Client-side (insecure) — what this challenge uses:
Browser downloads JS → JS contains password_hash → User decodes it locally

# Server-side (secure):
Browser sends credentials → Server validates → Server responds with session token
```

The fundamental problem is that any logic executed in the browser can be read and reversed by the user, since they control the JavaScript runtime environment.

**Ternary Operator Logic (equivalently):**

```js
// Original ternary:
return "YWRtaW4" !== t.u
  ? alert("Incorrect Username")
  : "cGljb0..." !== t.p
  ? alert("Incorrect Password")
  : void alert(`Correct Password! Flag: ${atob(t.p)}.`);

// Equivalent if-else:
if ("YWRtaW4" !== t.u) {
    alert("Incorrect Username");
} else if ("cGljb0..." !== t.p) {
    alert("Incorrect Password");
} else {
    alert(`Correct Password! Flag: ${atob(t.p)}`);
}
```

## Security Insights

- **Never perform authentication client-side:** All validation logic that protects resources must run server-side, where the user cannot inspect or modify it.
- **Never hardcode credentials in JavaScript:** Client-side JavaScript is fully visible to any user who downloads the page.
- **Base64 is not encryption:** Base64 is a reversible encoding — it provides zero security. Any "obfuscated" credentials in Base64 are trivially decoded with `atob()`.
- **Server-side password hashing:** Real applications store salted, hashed passwords (bcrypt, Argon2) server-side and perform the comparison there.

---

## Conclusion

The Login challenge perfectly illustrates why placing authentication logic in client-side JavaScript is fundamentally insecure. By simply opening the Developer Tools and calling `atob()` on the hardcoded Base64 string, we bypass the login entirely without ever sending a request to the server.
